# Flow.Ai

Модуль локального ИИ-ассистента FLOW. Отвечает за всё взаимодействие с LLM: генерацию черновиков задач, разделов ТЗ и диаграмм бизнес-процессов через локально запущенный Ollama.

Полное ТЗ: [`docs/TZ_ai_local_assistant.md`](../../docs/TZ_ai_local_assistant.md). План внедрения: [`docs/Instrukciya_ai_assistant_plan_vnedreniya.md`](../../docs/Instrukciya_ai_assistant_plan_vnedreniya.md).

## Что делает

Модуль не "думает сам по себе" — он оборачивает вызовы к локальной модели в предсказуемый, проверяемый пайплайн:

1. **Generator** — отправляет системную инструкцию + запрос пользователя в Ollama, получает сырой текстовый ответ.
2. **Validator** — детерминированный код (не LLM), проверяет, что ответ соответствует ожидаемому формату (валидный JSON с нужными полями, корректный Mermaid-синтаксис и т.п.).
3. **Retry-critic** — если валидатор не согласен, его причина отправляется модели обратно как сообщение критика, и генерация повторяется (по умолчанию до 3 раз).

Ничего из этого не пишет в БД само по себе — результат остаётся черновиком, который вызывающая сторона (UI/сервис) обязана показать пользователю на подтверждение (human-in-the-loop). Модуль ничего не решает за человека, только готовит варианты.

## Из чего состоит

| Папка | Назначение |
|---|---|
| `Options/OllamaOptions.cs` | Настройки: адрес Ollama, модель, температура, число попыток. Секция конфигурации `Ollama` в `appsettings.json` (Flow.Api). |
| `Client/` | `IOllamaClient`/`OllamaClient` — тонкая HTTP-обёртка над `/api/chat` Ollama. |
| `Agents/GeneratorAgent.cs` | Оркестрация Generator+Validator+retry, описанная выше. Универсальна — принимает любой `IAgentValidator`. |
| `Tasks/` | Конкретная реализация под создание задач: `TaskDraft` (черновик), системный промпт, `TaskDraftValidator` (проверка JSON-схемы `{title, priority, project_key}`). |
| `Diagrams/MermaidDiagramValidator.cs` | Структурная проверка Mermaid-диаграмм перед конвертацией в drawio XML: баланс скобок, наличие узлов/рёбер, ровно один блок `mermaid`. |
| `DependencyInjection/FlowAiServiceCollectionExtensions.cs` | `AddFlowAi(configuration)` — регистрирует всё вышеперечисленное в DI. |

## Почему так, а не иначе

- **Валидатор — всегда код, не LLM.** Проверять модель моделью ненадёжно; правильность формата (JSON, Mermaid) — задача, которую детерминированный парсер решает быстрее и точнее.
- **Mermaid-валидатор принимает и `flowchart`, и `graph`.** Эмпирически (на Qwen2.5-3B) модель устойчиво писала `graph TD` вместо явно запрошенного `flowchart TD`, и 3 попытки retry с точным указанием на ошибку это не исправляли. Оба варианта — валидный Mermaid, поэтому конвертер в XML должен принимать оба, а не бороться с моделью за конкретный токен.
- **Валидатор проверяет только формат, не факты.** `TaskDraftValidator` подтвердит валидный JSON, даже если модель перепутала `project_key` (в тестах так и происходило: явно указанный в тексте "FLW" модель иногда заменяла на выдуманный "PROD"). Проверка "существует ли такой проект на самом деле" — отдельная задача на стороне сервиса, использующего `Flow.Ai`, обычно через RAG с реальным списком проектов.

## Как запустить локально

1. Поднять Ollama и скачать модель:
   ```bash
   ollama serve
   ollama pull qwen2.5:7b-instruct-q4_K_M   # или qwen2.5:3b-instruct-q4_K_M для слабого железа
   ```
2. Указать модель в `appsettings.json` Flow.Api (секция `Ollama`) — по умолчанию уже настроено на 7B.
3. Запустить `Flow.Api`, дёрнуть демо-эндпойнт:
   ```bash
   curl -X POST http://localhost:5080/ai/tasks/draft \
     -H "Content-Type: application/json" \
     -d '{"text":"Срочно поправить баг с авторизацией в проекте FLW"}'
   ```
   Ответ — черновик задачи с числом попыток, потребовавшихся валидатору.

## Чего здесь ещё нет (следующие шаги)

По плану из `Instrukciya_ai_assistant_plan_vnedreniya.md`:

- **RAG** — индексация `docs/*.md`, задач и диаграмм через pgvector, чтобы генерация опиралась на реальную базу знаний проекта, а не только на инструкцию. Без этого модуль не может составлять содержательные ТЗ — только простые структурированные ответы вроде черновика задачи.
- **Diagram reader** — парсер `EntityDiagrams.XmlContent` в структурированный граф, для чтения уже существующих диаграмм.
- **Mermaid → mxGraph XML конвертер** — детерминированный код, довершающий генерацию диаграмм (сейчас есть только валидатор Mermaid, самого конвертера ещё нет).
- **Генерация секций ТЗ** — по аналогии с `Tasks/`, но с разбивкой по секциям шаблона и few-shot на существующих ТЗ проекта.
- **`AiGenerationLog`** — аудит всех генераций и решений пользователя (принял/отклонил).
