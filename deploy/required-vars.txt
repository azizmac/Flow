# Машиночитаемый список GitHub Variables и Secrets, от которых зависит выкатка Flow на хост
# (self-hosted раннер = сервер Flow, docker compose). Он же справочник для docs/TZ_cicd_host.md.
#
# Кто читает файл:
#   scripts/check-vars.sh        — джоба «Проверка · переменные» в .github/workflows/ci.yml;
#   scripts/check-compose-env.sh — сверка ${VAR} из compose-файлов со списком объявленных имён.
#
# Зачем список вообще нужен. Забытая переменная ничего не роняет: у каждой в compose есть дев-дефолт,
# контейнер стартует зелёным — и сервер уезжает с паролем «flow». Поэтому состав переменных проверяется
# до того, как что-то соберётся.
#
# Формат строки:  ИМЯ|тип|этап|описание
#   тип   — var (GitHub Variables) либо secret (GitHub Secrets);
#   этап  — с какого этапа переменная обязана быть задана:
#             1 — публикация образа (любой push в main);
#             2 — выкатка на хост (push в main и ручной запуск с main);
#   «-»   — не обязательна: пустое значение означает дефолт из compose (в .env на сервере не пишется).
#
# Разделитель — вертикальная черта, поэтому в описаниях её быть не должно.
# Значения попадают в .env на сервере в одинарных кавычках — одинарной кавычки в них быть не должно.

# ---- Реестр ----
REGISTRY|var|1|Реестр образов, по умолчанию docker.io
IMAGE_PREFIX|var|1|Владелец образов в реестре (учётка Docker Hub): образ становится REGISTRY/IMAGE_PREFIX/flow-api. Дефолта нет намеренно
REGISTRY_USERNAME|secret|1|Логин реестра для публикации образа. Лучше access token с правом записи, а не пароль учётки
REGISTRY_PASSWORD|secret|1|Пароль или access token реестра для публикации
REGISTRY_PULL_USERNAME|secret|-|Read-only логин, которым сервер тянет образ. Не задан — берётся пара публикации; не нужен, если образ публичный
REGISTRY_PULL_PASSWORD|secret|-|Read-only access token для pull на сервере

# ---- Хост ----
DEPLOY_DIR|var|-|Каталог установки на сервере: compose-файлы, docker/{ai,data}, .env, backups. По умолчанию /opt/flow. Пользователь раннера должен иметь в нём право записи и состоять в группе docker
DEPLOY_TIMEOUT|var|-|Сколько секунд ждать 200 от /health/ready после замены контейнера. По умолчанию 300
AUTH_ISSUER|var|2|Внешний адрес Flow, который видит браузер (http://server:8080 или https://flow.example.com за прокси). Попадает в claim iss — обязан совпадать с адресом, по которому открывают вход
API_PORT|var|-|Порт api на сервере. По умолчанию 8080
TZ|var|-|Пояс дат интерфейса. По умолчанию Europe/Moscow
AUTH_ALLOW_INSECURE_HTTP|var|-|true, пока Flow открывают по http (по умолчанию). За TLS-прокси — false; при PROXY_ENABLED=true CI сам подставляет false
PROXY_ENABLED|var|-|Поднять Caddy перед api (docker/caddy/Caddyfile): сертификат Let's Encrypt на домен из AUTH_ISSUER, который тогда обязан быть https://домен без порта. Роутер пробрасывает 80 и 443. Вместе с ним api начинает верить X-Forwarded-*, публикуется только на 127.0.0.1 и перестаёт принимать http на OpenIddict
API_BIND|var|-|На каком адресе сервера публиковать API_PORT. По умолчанию 0.0.0.0, при PROXY_ENABLED=true — 127.0.0.1: снаружи Flow тогда виден только через Caddy
CADDY_IMAGE|var|-|Образ Caddy, по умолчанию caddy:2.10-alpine
DATA_ROOT|var|-|Каталог для томов данных (postgres, minio, models). Действует только при создании томов
MODELS_ROOT|var|-|Отдельный каталог для весов моделей, перебивает DATA_ROOT/models

# ---- Данные ----
POSTGRES_DB|var|-|База приложения, по умолчанию flow
POSTGRES_USER|var|-|Пользователь БД, по умолчанию flow. Обязан быть суперпользователем: миграция делает CREATE EXTENSION vector
POSTGRES_PASSWORD|secret|2|Пароль БД. Не должен совпадать с дев-дефолтом flow. Менять после первого старта можно только вместе с паролем в самой базе
MINIO_ROOT_USER|secret|2|Он же S3__AccessKey
MINIO_ROOT_PASSWORD|secret|2|Он же S3__SecretKey, не короче 8 символов
S3_BUCKET|var|-|Бакет вложений, по умолчанию flow
BACKUP_ENABLED|var|-|Сервис бэкапов по расписанию (профиль backup). По умолчанию true
BACKUP_DIR|var|-|Куда класть бэкапы, по умолчанию DEPLOY_DIR/backups
BACKUP_CRON|var|-|Расписание бэкапа, по умолчанию 0 3 * * *
BACKUP_KEEP|var|-|Сколько копий держать, по умолчанию 7

# ---- Auth ----
AUTH_CERT_PASSWORD|secret|2|Пароль PFX Auth-модуля. Файлы создаются при первом старте в томе auth-certs; новый пароль к старым PFX — отказ на старте
BOOTSTRAP_PASSWORD|secret|2|Пароль первичной учётной записи. Смена обязательна при первом входе
BOOTSTRAP_ENABLED|var|-|Сидер первичной учётной записи. После первого входа можно false
BOOTSTRAP_ID|var|-|Guid первичного пользователя, общий у учётки и профиля
BOOTSTRAP_EMAIL|var|-|Почта первичной учётной записи
BOOTSTRAP_USERNAME|var|-|Логин первичной учётной записи
BOOTSTRAP_FIRST_NAME|var|-|Имя владельца
BOOTSTRAP_LAST_NAME|var|-|Фамилия владельца

# ---- Поиск и ИИ ----
SEARCH_ENABLED|var|-|Выключатель поиска целиком
SEARCH_INDEXING_ENABLED|var|-|Выключатель фонового индексатора
EMBEDDINGS_ENABLED|var|-|Умный поиск: false — только по словам, модели не нужны
AI_ENABLED|var|-|Поднимать сервис ai (llama-server) на сервере. По умолчанию false: без весов он не стартует — сперва ручной запуск CI с pull_models
AI_BACKEND|var|-|Профиль железа ai: cpu (по умолчанию) или cuda (docker/ai/nvidia.yml, нужен NVIDIA Container Toolkit)
AI_THREADS|var|-|Потоки моделей. Ниже 4 нельзя: батч индексации не укладывается в таймаут 60 с
AI_CTX_SIZE|var|-|Буферы llama-server. Дефолт 8192 на cpu и 2048 на cuda
AI_BATCH_SIZE|var|-|То же, дефолт 8192 на cpu и 512 на cuda
AI_UBATCH_SIZE|var|-|То же, дефолт 8192 на cpu и 512 на cuda. Ниже 512 нельзя
AI_IMAGE|var|-|Образ llama.cpp для cpu
AI_IMAGE_CUDA|var|-|Образ llama.cpp для cuda
EMBEDDINGS_MODEL|var|-|Имя модели эмбеддера = имя секции в docker/ai/models.ini
EMBEDDINGS_MODEL_FILE|var|-|Файл GGUF эмбеддера, по нему качает pull-models.sh
EMBEDDINGS_MODEL_URL|var|-|Откуда качать веса эмбеддера
RERANK_ENABLED|var|-|Вторая ступень выдачи (кнопка «Точнее»)
RERANKER_MODEL|var|-|Имя модели реранкера = имя секции в models.ini
RERANKER_MODEL_FILE|var|-|Файл GGUF реранкера
RERANKER_MODEL_URL|var|-|Откуда качать веса реранкера
VISION_ENABLED|var|-|Визуальный поиск по картинкам. Заодно включает закачку визуальных весов в pull_models
VISION_MODEL|var|-|Имя визуальной модели = имя секции в models.ini
VISION_MODEL_FILE|var|-|Файл GGUF визуальной модели, входит в её ModelVersion
VISION_MODEL_URL|var|-|Откуда качать веса визуальной модели
VISION_MMPROJ_FILE|var|-|Файл проектора визуальной модели
VISION_MMPROJ_URL|var|-|Откуда качать веса проектора
