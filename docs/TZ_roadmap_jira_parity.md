# План: модель задачи, представления, процесс, права, интеграции

Статус: **черновик**. Сводный документ к пяти ТЗ. Источник — сравнение Flow с Windshift
([Windshiftapp/core](https://github.com/Windshiftapp/core), self-hosted аналог Jira на Go/Svelte), сентябрь 2026.
Из найденных отличий в план взяты пять блоков. Портал для клиентов, база знаний, учёт времени, тест-менеджмент,
активы, ИИ-агенты и SSO в план не входят.

## Общие правила для всех блоков

- **Слои и права — как сейчас.** Хендлер: `ActorResolver` → проверка прав → инварианты. Права проверяет
  Application, домен знает только инварианты. Новые строки матриц — в `PermissionTests`, по тесту на строку.
- **Журнал пишут хендлеры.** Новые значения `TaskActivityType` только дописываются в конец enum (значения
  хранятся как int). Клиентские тексты журнала — без глаголов прошедшего времени (род актора неизвестен).
- **Индекс поиска.** Каждая новая команда, меняющая текст задачи или её принадлежность проекту, ставит `Upsert`
  в `ISearchIndexQueue` той же транзакцией. Поля, влияющие только на фильтры, индекс не трогают — как
  `TaskAssign` и `TaskSetDueDate` сейчас.
- **Миграции не меняют поведение.** Новые настройки по умолчанию воспроизводят текущее поведение:
  `WorkflowMode = Free`, `Visibility = Open`, экран по умолчанию, шаблон «Простой». Перенос данных — в `Up`
  вручную, как в `AddUserRoleAndStatus`.
- **Сквозные ключи для режима «Все проекты»** — enum'ы по образцу `StatusType`: `TaskTypeKind`, `TaskPriority`.
  Сущности проекта (статусы, типы, поля, спринты, вехи) между проектами не разделяются, общая конфигурация
  переносится копированием (`TZ_workflow_config`, «Наборы конфигураций»).
- **Shared не ссылается на Domain.** Новые enum'ы получают зеркала в `Flow.Shared` и маппинг в
  `*MappingExtensions`.
- **Клиент.** Фасады `Ds*`, тосты через `ToastService`, стили — токены + `app.css` + `mud-overrides.css`.
  Новые экраны — в чек-лист ручной проверки `docs/TZ_client_mudblazor.md`.
- **`AGENTS.md`** обновляется в конце каждого этапа: сущности, таблица API, СБД. Правило «плоский список
  (не канбан)» меняется на этапе 2B.

## Что сознательно сделано иначе, чем в Windshift

| Windshift | Flow | Причина |
|---|---|---|
| Статусы, типы, приоритеты — глобальные справочники + `configuration_sets` | статусы, типы, поля — в проекте; приоритет — enum | статусы уже живут в агрегате `Board`; живые общие наборы потребовали бы вынести их оттуда и переписать FK |
| Флаг `IsTask` у задачи = пункт чек-листа | чек-лист — отдельная owned-коллекция | подзадача и пункт списка — разные вещи |
| `DueDate` + `StartDate` + `EndDate` | `StartDate` + `DueDate` | третья дата не несёт смысла |
| Поиск — FTS (`english`) и «похожие» через LLM | остаётся гибридный векторный поиск Flow; FQL — отдельный точный язык для списка задач | семантический поиск у Flow сильнее, FQL его не заменяет |
| Команды — отдельная сущность | группа с флагом `IsTeam` | разница — один флаг |
| Смарт-коммиты от любого автора | только сопоставленный пользователь с правами, только ветка по умолчанию | иначе право push = право закрывать задачи |
